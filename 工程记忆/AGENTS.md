# AGENTS.md — 工程记忆维护规则

> 本文件是给 AI Agent 的 Schema 层指令。开始实质工作前应先读本文件、[`日志/README.md`](./日志/README.md) 与 [`主题/项目概览.md`](./主题/项目概览.md)。

## 项目边界

- 当前应用在 `../app/`；可再生产物只允许在 `app/node_modules/`、`app/dist/`、`app/.artifacts/`。
- 原始提取镜像在 `../sources/original-extraction/`，是只读 Raw sources，永不修改。
- 已接受的截图和报告在 `../evidence/`；新增证据必须使用新日期或运行标识，不能覆盖基线。

## 体系定位

本框架基于 Karpathy LLM Wiki 模式,三层架构:

1. **Raw sources(原始来源)** — Agent 读取的源文件、聊天记录、参考资料。只读,Agent 永不修改。
2. **The wiki(记忆本体)** — `日志/` 目录,记录每轮协作发生了什么。Agent 完全拥有,人类只读。
3. **The schema(本文件 + 日志/README.md)** — 维护规则,人类与 Agent 共同演进。

核心原则:**记忆是持久化、不断增值的产物**。交叉引用预先建好,矛盾预先标记,综合分析已反映所有已读内容。人类负责采集来源、提问、决策;Agent 负责摘要、归类、记账、维护 MOC 等所有"苦力活"。

## 何时写日志

每轮与用户完成**实质工作**后,写一篇日志。实质工作包括:实现功能、修复 Bug、修改 UI、配置/迁移/清理、测试/审查、架构讨论与计划。普通问答和一次性输出只留可追溯摘要,不写日志。

## 6 分类判断规则

每轮只有一个主要类型决定物理目录,按**主要交付物**归类:

1. 新功能、行为变化、重构 → `功能添加`
2. 纯界面/外观/样式调整 → `UI修改`
3. 已知异常的诊断、恢复、修复 → `Bug处理`
4. 解释、比较、架构讨论、计划、待办 → `工程讨论`
5. 只做测试、审查、检查、验收 → `测试验证`
6. 日志、wiki、文档、配置、依赖、清理、迁移 → `工程维护`

- 混合任务按主要交付物归类;实现过程包含测试仍归实现类(功能添加/UI修改/Bug处理)。
- 用户明确指定类型时优先采用用户类型。
- Agent 在开始实质工作前自动判断;本轮尚未封存时才能调整目录。

## 编号规则

- 六类分别从 `第001次` 起独立连续编号。
- 新编号 = 本类目录中现有最大编号 + 1,不参考其他分类。
- 日志身份 = "分类·第NNN次"(如 "Bug处理·第003次")。
- 不同分类可同时存在同名 `第001次.md`。

## 写日志 vs 写主题页

- **日志**(事件层):记录"这轮发生了什么"——决策、操作、文件变更、测试结果、下一步。封存后不改写;需要更正则新增轮次。
- **主题页**(知识层):长期有效的事实、决策、架构、流程。本模板暂不建主题页目录,留待实践扩展。当某事实在多轮日志中反复出现且长期有效时,Agent 应主动建议沉淀为主题页。

## MOC 维护

每写一篇日志,同步更新两处:

1. 所属分类的 `MOC_<分类>.md`(按本类编号倒序追加一行)
2. 总 MOC `日志/MOC_工作日志.md`(按跨分类时间倒序追加一行)

- 总 MOC 列:分类序号 | 时间 | 对话类型 | 目标 | 状态 | 主题标签 | 相关知识
- 分类 MOC 列:轮次 | 时间 | 目标 | 状态 | 主题标签
- 状态常用值:进行中 / 完成 / 阻塞 / 已放弃

## Obsidian 链接规范

- 用 `[[路径|别名]]` 双向链接。
- **表格单元格内**的别名竖线必须转义:`[[路径\|别名]]`,否则破坏表格列数。
- 路径以 `日志/` 为前缀(如 `[[日志/Bug处理/第003次\|Bug处理·第003次]]`)。

## 隐私边界

只记录:决策、命令目的、文件范围、测试摘要、错误类别、最终结果。
不复制:完整聊天正文、私人消息、内部推理、隐藏上下文、密钥、令牌、大段命令输出。

## 三大工作流

**摄取(Ingest)** — 用户投入新来源或新任务 → Agent 阅读 → 与用户讨论要点 → 按分类写一篇日志 → 更新所属分类 MOC 与总 MOC → (必要时)更新相关主题页。

**查询(Query)** — 用户提问 → Agent 读总 MOC 找相关分类 → 读分类 MOC 找相关轮次 → 读日志 → 综合带引用的答案。好的答案可回填为新主题页。

**健康检查(Lint)** — 用户要求时,Agent 检查:断链、孤儿页面(无入链)、编号不连续、MOC 与日志不一致、矛盾论断、过时信息。报告问题并建议修复,不擅自批量改动。

## 读取顺序(每次会话开始)

1. 本文件(`AGENTS.md`)
2. `日志/README.md`(分类规则与模板)
3. `日志/MOC_工作日志.md`(最近发生了什么)
4. 按当前任务相关分类读该分类 MOC 与最近 1-2 篇日志
5. 按任务阅读 `主题/` 中的相关页面。
