# David Whyte Experience 工程记忆

一套**可复用的工程记忆管理基础框架模板**,基于 [Karpathy 的 LLM Wiki 模式](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f),面向"与 AI Agent 协作"场景,提供日志分类体系与记忆维护规则。

> 本记忆以“当前已验收重建版本”为起点，持续记录后续协作；不补写历史聊天流水账。

## 这是什么

传统 RAG 每次查询都从原始文档重新检索,知识不累积。本框架采用另一种思路:让 Agent **增量地构建并维护一个持久化的工程记忆 wiki**——一套结构化、相互链接的 Markdown 文件。每轮与 Agent 协作的工作都会被归类记入日志,长期有效的事实/决策再沉淀为主题页。记忆随使用不断增值。

详见 [`llm-wiki.md`](./llm-wiki.md)(理念原文)，以及 [`主题/项目概览.md`](./主题/项目概览.md)。

## 三层架构

| 层 | 说明 | 落地 |
| --- | --- | --- |
| Raw sources(原始来源) | 策展的源文件,只读,Agent 只读不写 | 实践中自然形成,模板不强制建目录 |
| The wiki(记忆本体) | Agent 生成并维护的 Markdown | `日志/` 目录(事件层)+ 未来可扩展主题页 |
| The schema(规则) | 告诉 Agent 如何维护记忆 | [`AGENTS.md`](./AGENTS.md) + [`日志/README.md`](./日志/README.md) |

## 目录结构

```
工程记忆/
├── README.md              ← 本文件
├── llm-wiki.md            ← 理念源文档(Karpathy)
├── AGENTS.md              ← Schema:给 Agent 的记忆维护规则
├── 主题/                   ← 长期有效的项目知识
└── 日志/
    ├── README.md          ← 分类规则、编号、日志模板、隐私边界
    ├── MOC_工作日志.md    ← 总 MOC:跨分类时间线
    ├── 功能添加/MOC_功能添加.md
    ├── UI修改/MOC_UI修改.md
    ├── Bug处理/MOC_Bug处理.md
    ├── 工程讨论/MOC_工程讨论.md
    ├── 测试验证/MOC_测试验证.md
    └── 工程维护/MOC_工程维护.md
```

## 6 类日志分类

| 分类 | 适用场景 |
| --- | --- |
| 功能添加 | 新功能、行为变化、重构 |
| UI修改 | 纯界面/外观/样式调整 |
| Bug处理 | 已知异常的诊断、恢复、修复 |
| 工程讨论 | 解释、比较、架构讨论、计划、待办 |
| 测试验证 | 只做测试、审查、检查、验收 |
| 工程维护 | 日志、wiki、文档、配置、依赖、清理、迁移 |

判断规则与日志模板见 [`日志/README.md`](./日志/README.md);Agent 维护指令见 [`AGENTS.md`](./AGENTS.md)。

## 快速开始

1. 把整个 `工程记忆构建/` 目录复制到你的项目根下(可重命名为 `<项目名>-Wiki` 或直接叫 `Wiki`)。
2. 全局替换 `<项目名>` 为真实项目名。
3. 把 `AGENTS.md` 的内容并入项目的 Agent 指令文件(如 `CLAUDE.md` / `AGENTS.md` / `.workbuddy/` 配置),或直接让 Agent 读取本目录。
4. 开始与 Agent 协作——每轮实质工作结束后,Agent 会按分类写一篇日志并更新 MOC。
